= Multiple databases (MultiDB)
:description: This page describes multiple databases within an Aura instance and how to create and connect to a database. When connecting, select the target database using the connection bar or driver configuration.

label:AuraDB-Business-Critical[]
label:AuraDB-Virtual-Dedicated-Cloud[]

An Aura instance is fully-managed DBMS represented by a single instance ID, that is running in the Neo4j Aura cloud.
Every Aura instance includes a default database named `neo4j` and an internal `system` database, which cannot be deleted. 
With MultiDB enabled, an instance can host additional databases that share the instance's compute and storage resources.

AuraDB Business Critical and AuraDB Virtual Dedicated Cloud support multiple databases within an AuraDB instance. 
Create and manage databases using the Aura Console or the Aura API. 
An instance has its own compute and storage, and the databases run within the instance.
Use multiple databases when you need to separate data within a single instance.

[IMPORTANT]
====
This feature is in preview and is offered as-is and should only be used for internal development purposes and not in production.
The MultiDB preview is governed by the link:https://legal.neo4j.com/#aura-specific-terms[Experimental Service Terms] in your customer agreement with Neo4j.
====

== Resource sharing

All databases share the instance’s compute and memory resources. 
The maximum number of databases depends on the memory size (RAM) of the instance.
Up to five databases can be created per GB of RAM, with a maximum of 100 databases per instance.

[cols="1,1", options="header"]
|===
| Available instance memory | Maximum databases

| 2GB
| 10

| 4GB
| 20

| 8GB
| 40

| 16GB
| 80

| 32GB
| 100
|===

=== Manage databases

Create, view, and manage databases from the instance *Databases* view. Access it:

* From the *instance* (three dots) menu, select *Databases*.
* Alternatively, open *Inspect* and select the *Databases* tab.

=== Create a database

//https://neo4j.com/docs/operations-manual/current/database-administration/#manage-databases-default

To create additional databases, from the more menu (three dots), select *Databases*.
Select *Create Database*. 

A database name is generated automatically (for example, `293fd870`).

== Benefits 

* Lower administrative overhead compared to running multiple instances (no need to manage multiple instances)
* Development and test environments
* Different teams or features can use the same instance
* Faster to create and delete than separate instances

== Use case

Instead of running separate instances for production, development, and training, and sample data, they can be combined into a single instance.

An 8GB instance could be allocated as:

* `Production` 4GB 
* `Development` 2GB 
* `Training` 1GB
* `Sample dataset` 1GB (for experimenting with queries, dashboards, and new features)

== Feature support

=== Supported features

Multiple databases are supported across Aura tools.
For working with multiple databases, see the following documentation:

* xref:managing-instances/backup-restore-export.adoc#_backups_in_multiple_database_instances[Backup, export, and restore]: Take snapshots of your databases.
* xref:explore/introduction.adoc[Bloom] and xref:query/introduction.adoc[Query]: When connecting, select the target database using the connection bar.
* xref:metrics/view-metrics.adoc#_multiple_databases[Metrics]: Switch between databases using the Database dropdown in Metrics.
* xref:import/introduction.adoc[Import]: Select both the instance and the target database when running an import.

=== Unsupported features

Some features are not available for MultiDB instances:

* Databases cannot be created using Cypher database management commands (database management commands are disabled)
* Instance clone, CDC, Secondaries, Tool Authentication (Seamless login)
