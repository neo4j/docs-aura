= Multiple databases (Preview feature)
:description: This page describes multiple databases within an Aura instance and how to create and connect to a database.

label:AuraDB-Business-Critical[]
label:AuraDB-Virtual-Dedicated-Cloud[]


AuraDB Business Critical and AuraDB Virtual Dedicated Cloud support multiple databases within an AuraDB instance. 
You can create and manage databases using the Aura console or the Aura API. 
Each instance has its own compute and storage, and the databases run within the instance.



Use multiple databases when you need clear separation of data within a single instance, without managing multiple instances.

* Lower administrative overhead compared to running multiple instances
* Development and test environments in one instance
* Different teams or features working in the same instance
* Faster to create and remove than separate instances

Example: You can create lightweight, isolated databases for individual tenants (such as customers or groups), scaling from a few to hundreds within one instance.


For example, instead of running separate instances for production, development, and training, and sample data, they can be combined into a single instance.

An 8GB instance could be allocated as:

* `Production` 4GB 
* `Development` 2GB 
* `Training` 1GB
* `Sample dataset` 1GB (for experimenting with queries, dashboards, and new features)

== Limits (RAM and maximum databases)

All databases share the instance’s compute and memory resources. 
By default a maximum number of 5 databases per GB of RAM can be provisioned.
The maximum number of databases depends on the memory size (RAM) of the instance and there is an upper limit of 100 across all configurations.

[cols="1,1", options="header"]
|===
| Available instance memory | Maximum databases

| 2GB
| 10

| 4GB
| 20

| 8GB
| 40

| 16GB
| 80

| 32GB and above
| 100
|===

== Multiple database in the Aura console

=== Enable multiple databases

[IMPORTANT]
====
You must enable multiple databases during instance creation. 
This setting cannot be changed later.
====

On instance creation, scroll down to *Additional settings* during instance creation and enable *Multiple databases*.

[.shadow]
.Multiple databases toggle
image::multidb/multidb-toggle.png[]

=== Manage databases

You can create, view, and manage databases from the instance Databases view. 
You can access it from:

* From the instance [...] more menu > select *Databases*
* Open *Inspect* > select the *Databases* tab.

=== Create a database

To create additional databases, from the instance [...] more menu > select *Databases* > select *Create Database*. 

A database name is generated automatically (for example, `293fd870`). 

[NOTE]
====
Databases cannot be created using Cypher database management commands, only via API and Aura console.
====

== Manage multi-database instances via Aura API

Standard guidance for Creating API credentials applies, see link:{neo4j.docs-base-uri}/aura/api/overview/[Aura API].

[NOTE] 
====
All endpoints below now require your Organization ID and Project ID in the path, in addition to your Instance ID.
====

MultiDB uses the beta version of the Aura API. 
Use link:https://neo4j.com/docs/aura/platform/api/specification/?urls.primaryName=Aura%20v2beta1[https://api.neo4j.io/v2beta1] as the base URL.

=== Create a multi-database instance via API

[source]
----
POST /organizations/{orgId}/projects/{projectId}/instances

curl -X POST "https://api.neo4j.io/v2beta1/organizations/$ORG_ID/projects/$PROJECT_ID/instances" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "version": "5",
    "region": "europe-west1",
    "memory": "4GB",
    "storage": "8GB",
    "name": "MYMULTIDBTESTINSTANCE",
    "type": "enterprise-db",
    "cloud_provider": "gcp",
    "multi_database": true
  }'
----

=== Create additional databases via API

[source]
----
POST /organizations/{orgId}/projects/{projectId}/instances/{instanceId}/databases

curl -X POST "https://api.neo4j.io/v2beta1/organizations/$ORG_ID/projects/$PROJECT_ID/instances/$INSTANCE_ID/databases" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "mydb"
  }'
----

=== Instance details

[source]
----
GET /organizations/{orgId}/projects/{projectId}/instances/{instanceId}/databases
----

=== Database details

[source]
----
GET /organizations/{orgId}/projects/{projectId}/instances/{instanceId}/databases/{databaseId}
----

=== Delete database

[source]
----
DELETE /organizations/{orgId}/projects/{projectId}/instances/{instanceId}/databases/{databaseId}
----

== Connecting with Drivers

[.tabbed-example]
====
[.include-with-Python-example]
=====

[source, python]
----
from neo4j import GraphDatabase

uri = "neo4j+s://instanceid.databases.neo4j.io"
username = "neo4j"
password = "xxxxxxxxxxxxxxxx"
database = "my_database_id"

driver = GraphDatabase.driver(uri, auth=(username, password))
with driver.session(database=database) as session:
    result = session.run("MATCH (n) RETURN count(n) AS node_count")
    print(result.single())
----
=====
[.include-with-javascript-example]
=====

[source, javascript]
----
const neo4j = require('neo4j-driver');

const uri = "neo4j+s://instanceid.databases.neo4j.io";
const user = "neo4j";
const password = "xxxxxxxxxxxxxxxx";
const database = "my_database_id";

const driver = neo4j.driver(uri, neo4j.auth.basic(user, password));

async function main() {
  const session = driver.session({ database });
  const result = await session.run("MATCH (n) RETURN count(n) AS node_count");
  console.log(result.records[0].get("node_count").toInt());
  await session.close();
  await driver.close();
}

main();
----
=====
====

== Connecting external sources

When connecting to a multi-database instance from an external client, specify the `database name` as part of the connection. 
The database name identifies which database to access. 
If no database name is provided, the connection cannot be established.
This applies to drivers, the Query API, and other external sources.

== Features

=== Supported features

Multiple databases are supported across Aura tools. 
There are some things to consider when working with multiple databases:

* xref:managing-instances/backup-restore-export.adoc#_multi_database_instances[Backup, export, and restore]: Take backups of individual databases.
* Bloom and Query: When connecting, select the target database using the connection bar.
* Metrics: Switch between databases using the Database dropdown in Metrics.
* Import: Select the instance and the target database when running an import.
* link:https://neo4j.com/docs/aura/platform/api/specification/?urls.primaryName=Aura%20v2beta1[Aura API]
* Security & Networking: Instance level SSO, IP Filtering & Private Endpoints (where available for Tier)

=== Coming features

While multiple databases are in preview, not all features of Aura are supported yet.
Future releases will include support for:

* Pause and resume for instances or individual databases
* Custom database naming or renaming
* Default database management
* Instance level backup & restore
* Activity Feed 

=== Unsupported preview features

Some features are not yet in scope for multi-database instances, such as instance clone, CDC, Secondaries, Tool authentication (aka Seamless login), and Custom Endpoints.
