= Filters
:description: Use parameters in your dashboards to further customize queries or use them in filters for node and relationship properties.

Filters are the main way to make dashboard charts dynamic.

Filters can be created in two ways:

* Add a filter and parameter
* Link a parameter to a filter

== Add a filter and parameter

Create a filter to see which companies are based in a city, with the default set to London.

.Example: Filter to see which companies are based in a city with the default showing London

=== Step 1: Define the filter

. On the **Dashboards** page, select **Add filter**.
. Choose filter type `Node property`.
. Select the label `Customer`.
. Select the property `City`.

In the right pane, you can see a preview of how your filter will look and also interact with it.

=== Step 2: Link the parameter

. A parameter named `$customer_city` is created automatically.
. Set the default value to `London`.
. Select **Save**.

=== Step 3: Add a card

Paste the following query into the Cypher input, then select *Save*:

.Cypher query for a table which displays customers within a city
[source,cypher]
----
MATCH (n:Customer)
WHERE n.city = $customer_city
RETURN n.companyName AS `Company name`
----

. Select **Add**.

.How to set up a parameter with a number value of 4 named "unit_param"

=== Step 3: Add a card 

. Add a card.
+
. Paste the following Cypher into the card, then select **Save**:

.Cypher query for a table which displays products with a certain number of units in stock
[source,cypher]
----
MATCH (p:Product)
WHERE p.unitsInStock = $unit_param
RETURN p.productName AS product, p.unitsInStock AS units
LIMIT 10
----

=== Step 4: Define the filter

. Add a filter.
. Select the filter type `Node property`.
. Select the label `Product`.
. Select the property `unitsInStock`.

=== Step 5: Link the existing parameter

. Select **existing parameter**, then select `$unit_param`.
. The default value is `4` (changing it overrides the parameter default).
. Select **Save**.


The parameter and filter are now connected.

Selecting a value from the dropdown updates the parameter `$unit_param` and updates the table.

== Filter types

We support 7 different filter types to make dashboards more interactive. 
You can filter using free text, numbers or dates, or go fully custom with the “custom query” type. 
The filter creation experience has a live preview to help you create filters.

* Node property (Filters nodes based on their properties, so the filter answers: "Show me nodes with these properties.”)
* Relationship property (Filters nodes based on properties and their connected relationships? So the filter answers: “Show me nodes that are connected via relationships with these properties.”)

=== Free text filter

A Free text filter is basically just a text field, and whatever the user types in there is sent to a parameter. 
It is commonly used as a search field.

For example, I can have a Free text filter that is tied to a parameter called `$free_text_search`. 
I can then have a table card listing all movies that contains this search phrase in their title. 
This is accomplished by adding that parameter into the table card's cypher query such as:

[source,cypher]
----
MATCH (m:Movie) 
WHERE m.title CONTAINS $free_text_search 
return m.title
----

Note that you don't write any query to create a free text filter.

=== Custom query filter

You have to write a query for a custom query filter. 
This filter is showing a *Select component* for the user (not a text field). 
And you write the query to populate the values for the dropdown of the *Select component*.

?**The query can return data even though the user hasn't typed in a search phrase. But when the user types in a search phrase, it will be available to the query as a parameter called $input. And that can be used to filter the returned data.
This is more descriptive in my opinion that the word "search the graph".**?

You can basically list any kind of things here, like movie titles from a specific movie, or any custom thing you want. 
For example:

[source,cypher]
----
MATCH (n:Movie) //looks for Movie nodes
WHERE n.title 
CONTAINS $input //Checks whether n.title contains what the person typed
RETURN n.title //Returns matching titles
LIMIT 10 //Caps the list at 10 so it stays light and responsive
----

Customers sometimes use it when they want to have full control over their query. Otherwise they can use our existing Node filters. But for customers with large datasets, they want to tailor their query for performance optimization. So they may want to use some specific cypher syntax

== Parameters drawer

.The parameters drawer
[.shadow]
image::dashboards/parameters-and-filters/parameters-drawer.png[]

The drawer shows the dashboard parameters in alphabetical order.
Each parameter has an icon next to it hinting at its data type:

* A text icon for strings.
* A hashtag icon for numbers.
* A calendar icon for dates.
* A filter icon for unspecified data types. 

=== Creating a parameter in the parameter drawer

. From the **Parameters** drawer, use the **Add** button.
. In the dialog, enter a parameter name, select a data type and optionally an initial value for the parameter, then **Save**.

=== Editing a parameter

. From the **Parameters** drawer, hover over the parameter you wish to edit.
. In the dialog, edit the parameter name, data type and/or initial value, then **Save**.

=== Using a parameter in a query

To use a parameter in a query, prefix the parameter name with `$`.
For example, to use a parameter with a number value of 4 and the name "unit_param", use `$unit_param` in your query:

// .Cypher query for a table which displays products with a certain number of units in stock

// MATCH (p:Product)
// WHERE p.unitsInStock = $unit_param
// RETURN p.productName as product, p.unitsInStock AS units
// LIMIT 10
