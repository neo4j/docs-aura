= Filter types
:description: Examples of how to filter data using Aura Dashboards, with complete Cypher examples to set up filters and cards. This means that your dashboard reports can show different data depending on the value of a parameter.

// In Neodash this was called "Parameter Select" https://neo4j.com/labs/neodash/2.3/user-guide/reports/parameter-select/


Use filters to make dashboards more interactive, with node properties, relationship properties, free text, custom queries, and date, datetime, number, and boolean filters.

The filter creation experience has a live preview to help you create filters.

You can type or write into a filter *Select component* which is a selectable or writable field, with dropdowns of the options. 
Simply put, a parameter select component lets users set a query parameter dynamically (e.g. `$supplier`).
This means that your reports can show different data depending on the value of a parameter.

== Node property 

Filters nodes based on their properties.
//A node property selector lets users choose a property from a node with a given label, to be used as a parameter in the dashboard.

This example uses a filter to select specific products. 
We will create a product name picker where a user selection from the dropdown writes to the parameter input $productname, so the user input can be used on a card to show if products are in stock.
// This populates a dropdown from  :Product(productName) values and stores the selection in the linked $productname parameter.

1) Add a filter

* Set *Filter type* to `Node property`
* Choose Label: `Product`
* Choose Property: `productName`
* Link parameter, use a new or existing parameter, (for example: `$product_productname`)
* (Optional) Set a default value (for example, `Alice Mutton`)

2) Add a card

* Use the linked parameter in the query, for example:

[source,cypher]
----
MATCH (p:Product)-[:PART_OF]->(c:Category)
WHERE p.productName = $product_productname
RETURN
  p.productName AS product,
  c.categoryName AS category,
  p.unitPrice AS unit_price,
  p.unitsInStock AS units_in_stock
----

.Node property

== Relationship property 

Use this filter when the value you want to filter by properties on a relationship rather than on the nodes themselves.
// A relationship property selector lets users choose a property from a relationship with a given type, to be used as a parameter in the dashboard.

This example uses a relationship property filter to select a discount value from the ORDERS relationship and store it in the `$orders_discount` parameter.
// This example uses a relationship property filter to select an order discount and apply it to a card query.
The filter gives discount values (for example selecting 0.1 would be 10% discount).

1) Add a filter

* Select *New Filter*
* Filter type: `Relationship property`
* Relationship type: `ORDERS`
* Property: `discount`
* Link parameter: `$orders_discount`

2) Add a card

* Use the linked parameter in the query, for example:

[source,cypher]
----
MATCH ()-[o:ORDERS]->(p:Product)
WHERE o.discount = $orders_discount
RETURN
  toString(toInteger(o.discount * 100)) + "%" AS discount,
  p.productName AS name,
  count(*) AS total_products
ORDER BY total_products DESC
LIMIT 20
----

When a a discount value is selected in the filter, the card reruns using that value and updates the results automatically.

== Free text

A free text filter is essentially a text field that is commonly used for search. 
Type any string value, and it sends what is typed into a parameter, which can then be used as a parameter inside dashboard queries.

This example filters orders by shipping postcode.
A free text filter is tied to a parameter called `$text`. 
The card then lists all products names that contains the search.

1) Add a filter

* Filter type: `Free text`
* Link parameter: `$text`

2) Add a card

* Use the linked parameter in the query, for example:

[source,cypher]
----
MATCH (o:Order) 
WHERE o.shipPostalCode CONTAINS toUpper($text)
RETURN DISTINCT
  o.shipPostalCode AS postcode,
  o.shipCity AS city
----

// In summary, this query retrieves unique combinations of shipping cities and postal codes for orders, filtering based on whether the input text matches the postal code (ignoring case and spaces) or if no input is provided.

As the person types a postcode, the card updates automatically to show matching orders.

== Custom query

Use a Cypher query to populate the select component.
When someone chooses an option or enters a phrase, that value is passed as a parameter to the card’s Cypher query.

The query can return data even though the user hasn't typed in a search phrase. 
But when the user selects and option or types in a search phrase, it will be available to the query as a parameter, and that can be used to filter the returned data.

Use a custom query filter for full control over a query (otherwise use the existing node property or node relationship filters). 
For large datasets, you may want to tailor the query for performance optimization and use a specific cypher syntax.

1) Add a filter

* Filter type: `Custom query`
* Enter the custom query: 

[source,cypher]
----
MATCH (c:Customer)-[:PURCHASED]->(o:Order)
WITH c.companyName AS value, count(o) AS orders
RETURN value
ORDER BY orders DESC
LIMIT 3
----

* Link parameter: `$custom`

The output of this filter will be the names of the three companies that have made the most purchases.

.Custom query filter
image::dashboards/filters/customqueryfilter.png[Custom query filter]

2) Add a card 

* Use the linked parameter in the query, for example:

[source,cypher]
----
MATCH (c:Customer)-[:PURCHASED]->(o:Order)-[op:ORDERS]->(p:Product)
WHERE $custom IS NULL OR c.companyName = $custom
RETURN
  p.productName AS product,
  sum(op.quantity) AS units,
  round(sum(op.unitPrice * op.quantity), 2) AS revenue
ORDER BY revenue DESC
LIMIT 10
----

The output will provide insights into which products are generating the most revenue from purchases, optionally filtered by a specific company name.

== Date / Datetime

[NOTE]
====
This example was trickier to make with Northwind dataset because of how the Northwind dataset is constructed. `1996-07-04 00:00:00.000` is not a valid datetime string, the correct one would be `1996-07-04T00:00:00.000`.
====

A date / datetime filter lets people filter based on dates by using a calendar, or by typing a date format.

1) Add a filter

* Filter type: `Datetime`
* Important! The filter must have *Enable time zone selection* selected because the Northwind dates use time zone
* Link parameter: `$datetime`

2) Add a card

* Use the linked parameter in the query, for example:

[source,cypher]
----
MATCH (o:Order)
WHERE $datetime < datetime(replace(o.orderDate," ","T"))
RETURN o.orderDate, o.orderID, o.shipCountry
----

Use the calendar or type `07/04/1996, 00:00  UTC` and the card will update with order date, order ID and ship country. 

.Datetime
image::dashboards/filters/datetime.png[Date time]

== Number

*Integer*: A Number filter lets people filter data using numeric values or ranges.
It's whole numbers.
*Float*: It’s useful for prices, quantities, counts, scores, or thresholds.
It can be a number with a decimal point. 

How the filter works: whatever number the person enters gets passed into the query as $number, and the query uses it to include or exclude results.

1) Add a filter

* Example: filter products by unit price.
* Filter type: `Number`
* Link parameter: `$unit_price`

2) Add a card

[source,cypher]
----
MATCH (p:Product)
WHERE p.unitPrice = $unit_price
RETURN p.productName, p.unitPrice
----

== Boolean

A Boolean filter stores either true or false in a linked parameter. 
You can rename the values and switch between them by selecting one of the two options (e.g. to `Yes` or `No`)

Example: show products that are in stock (true), or not in stock (false).

1) Add a filter

* Filter type: Boolean
* Link parameter: `$in_stock`
* Label for true: `In stock`
* Label for false: `Out of stock`
* (Optional) Set the default value to *True*

2) Add a card

[source,cypher]
----
MATCH (p:Product)
WHERE ($boolean = true AND p.unitsInStock > 0)
   OR ($boolean = false AND p.unitsInStock = 0)
RETURN p.productName, p.unitsInStock
ORDER BY p.productName;
----
