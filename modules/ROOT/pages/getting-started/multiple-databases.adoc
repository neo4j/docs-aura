= Multiple databases 
:description: This page describes Multiple databases within an Aura instance and how to create and connect to a database.

label:AuraDB-Business-Critical[]
label:AuraDB-Virtual-Dedicated-Cloud[]

It's possible to create multiple databases within an instance using the Aura console UI or with the Aura API.
You can do this if you want to have less administrative overhead compared to running multiple instances, and also it's a good idea if you want to reduce your costs. 
Now let's dig into the technicalities of multiple databases. 

First, make sure you have Toggled on multiple databases when you are setting up your instance for the first time - this is a prerequisite because you cannot enable multiple databases retroactively. 

To create a database, first connect to your instance as usual. [see link]
Then under the three dots where you can inspect the instance's details, go to the databases tab. 

Use the *Create Database* to add a new database to the instance. 
At the moment, it will automatically get a default database name such as `293fd870`.
It's not yet possible to change that name.

== Managing databases

You can access all database details from *Inspect > Databases* within a running AuraDB instance.

The table lists all databases in the instance and shows:

* Database name
* Whether it is the default
* Number of nodes and relationships
* Status (e.g. `CREATING` or `RUNNING`)

A status of RUNNING means the database is online and ready to accept connections.

The three-dot menu at the end of each row provides database-specific management actions.
Use the search bar to filter databases by name.

== Backups

From *Inspect > Backups* there’s a dropdown labeled “Select Database.”
Choose which database inside the instance you want to view or back up.

== Database administration

Aura automatically handles the system database and administrative routing for you.

// The system database is included for administrative tasks, but it is not used for exploring graph data.

// Neo4j supports the management of multiple databases within the same DBMS. 
//The metadata for these databases, including the associated security model, is maintained in a special database called the system database. 
//All multi-database administrative commands must be run against the system database. 
//These administrative commands are automatically routed to the system database when connected to the DBMS over Bolt.
