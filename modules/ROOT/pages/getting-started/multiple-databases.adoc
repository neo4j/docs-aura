= Multiple databases 
:description: This page describes Multiple databases within an Aura instance and how to create and connect to a database.

label:AuraDB-Business-Critical[]
label:AuraDB-Virtual-Dedicated-Cloud[]

You can create multiple databases within a single Aura instance using the Aura Console or the Aura API.

== Use cases

Use multiple databases when you want clear separation inside a single Aura instance.

* Less administrative overhead compared to running multiple instances
* Development and test environments
* Different teams or features working in the same instance

This approach keeps things organised without the overhead of running multiple instances, which can also help reduce costs.
All databases share the same compute and memory resources, so this works best when you don’t need dedicated resources for each database.

== Max number of databases

All databases share the instance’s compute and memory resources.
The max number of databases is tied directly to the memory (RAM) of your instance.
e.g. 4GB instance supports up to 4 databases.

[IMPORTANT]
====
You must enable multiple databases during instance creation. 
This setting cannot be changed later.
====

To create a database, connect to your instance, then from the more menu (three dots) where you can inspect the instance's details, go to the databases tab. 

Use the *Create Database* to add a new database to the instance. 
It will automatically get a default database name such as `293fd870`.

== Manage multiple databases

You can access all database details from *Inspect > Databases* within a running AuraDB instance.

The table lists all databases in the instance and shows:

* Database names (the default database is labeled) 
* Number of nodes and relationships
* Status (e.g. `CREATING` or `RUNNING`) The status `RUNNING` means the database is online and ready to accept connections.

The three-dot menu at the end of each row provides database-specific management actions.
Use the search bar to filter databases by name.

== Backups

From *Inspect > Backups* there’s a dropdown labeled “Select Database.”
Choose which database inside the instance you want to view or back up.

== Database administration

Aura manages the system database and handles administrative routing automatically, so you don’t need to manage this yourself.

// The system database is included for administrative tasks, but it is not used for exploring graph data.

// Neo4j supports the management of multiple databases within the same DBMS. 
//The metadata for these databases, including the associated security model, is maintained in a special database called the system database. 
//All multi-database administrative commands must be run against the system database. 
//These administrative commands are automatically routed to the system database when connected to the DBMS over Bolt.

== Explore and Query

In Explore and Query, use the https://neo4j.com/docs/aura/query/visual-tour/#_connection_bar[connection bar] to select the database you want to work with.

//The dropdown lets you choose which database your Explore session connects to.

== Metrics

In *Metrics > Database tab*, use the dropdown to switch between databases in the instance.

== Import

You are prompted to choose an instance, and a database to run your import.

== Current limitations

These features are not yet available for multi-database instances:

* Custom database naming or renaming
* Pause and resume for instances or individual databases
* Backup and restore for multi-database-enabled instances
* Aura Agents (tool authentication is not supported)
* Resource allocations are pre-tuned during early preview
